# PATCHES.md — vendored patch stack for Dockerfile.qwen38-gb10

Every file here is vendored verbatim from a public repo at a pinned commit
(see `SHA256SUMS`; kernel-det sources are additionally byte-identical to the
sha256 pins in blazux's Dockerfile). Nothing was edited except
`apply_ple_force_fp8.py` and `patch_modelopt_fp8_block_moe.py`, which are our
faithful guarded ports (their originals are pinned by sha256 in the table:
getrefined's `ple-force-fp8.patch` is kept alongside for provenance; MiaAI's
`patch_modelopt_fp8_block_moe.py` is referenced by hash) so the image build
does not depend on `patch`/`git` being present in the base image, and patch 9
operates in place on the image's own files.

License note: everything here is Apache-2.0 (blazux/tsw2k/getrefined/jschmied
lineage) except the two files vendored from MiaAI-Lab
(`patch_checkpoint_config.py`, and the original our patch 9 ports), which are
AGPL-3.0-or-later. Both are used internally on our own cluster and the
artifacts are not distributed; do not publish them without honoring AGPL.

## What is deliberately NOT in this image

- **MiaAI's `patch_ple_layer.py`** (PR #53899-style dtype dispatch, NVFP4-PLE runtime, packed-table offload) — solves the same PLE gap our patch 0 solves, but dispatches on `text_config.ple_embedding_dtype`, which the nvidia checkpoint does not declare (their stack pairs it with `detect_ple_dtype.py` + `--hf-overrides` injection). Our env-forced `PLE_FORCE_FP8=1` (getrefined backport) covers the nvidia checkpoint's FP8-PLE layout directly; their NVFP4-PLE machinery targets the local-inference-lab checkpoint we do not serve. Kept ours; documented as equivalent-for-our-checkpoint.
- **MiaAI's `patch_modelopt_mxfp8.py`** (MXFP8 shape fallback to BF16 emulation) — the nvidia checkpoint has NO MXFP8 layers (verified: quant_algo histogram over its config.json = NVFP4×48, FP8×1, FP8_BLOCK_SCALES×1; dense layers are BF16). Only needed for the RadixArk/local-inference-lab checkpoints.
- **MiaAI's reduced-vocabulary MTP drafting** (`patch_mtp_draft_vocab.py` + `build_draft_vocab.py`) — output-safe but a measured *trade*: acceptance 56.5% → 47.8% with balanced shards, the `copy` task below baseline; their own README calls it "a real trade, not a free win" and ships it off by default. Revisit only if decode bandwidth becomes the binding constraint and a much larger corpus is built.
- **MiaAI's QSA gb10 launch profiles** (`files/qsa_gb10/`) — the 48-SM tile table is "a starting point, not a result"; their own default is `stock`. Candidate for a later benchmarking pass.
- **MiaAI's FP8-dense hybrid checkpoint** (`files/fp8dense/`) — builds a different checkpoint; we serve the official nvidia checkpoint as published (Jun's requirement). Not quality-validated by MiaAI either (GSM8K/AIME "still owed").
- **MiaAI's PLE CPU-offload stack** (`patch_ple_offload.py`, `ple_offload/`, `build_ple_packed_table.py`) — GB10-fixed but built for the NVFP4 PLE table; our lanes (mmap default, tsw2k offload fallback) cover the FP8 table. MiaAI measured it needs ~51 GB free CPU RAM and OOMs on their box — same conclusion as tsw2k's.
- **MiaAI's NFS weight sharing** — spec forbids NFS for the PLE mmap lane (per-node NVMe copy mandatory); rejected.
- **MiaAI's hardcoded `NCCL_IB_GID_INDEX=3` + `NCCL_IB_AUTO_DETECT=0`** — REJECTED: tsw2k caught GID index drifting (4 vs 3) after a link bounce on this fabric (~250 GID indices on forge); auto-detect stays.
- **MiaAI's `--safetensors-load-strategy lazy` / GMU 0.835 / MTP=3 / MAX_NUM_SEQS=8 / port 8888** — TP2-shaped measurements; our TP4 defaults stay tsw2k-proven. Documented as EXTRA_ARGS/MTP/env overrides.
- **blazux patch 9 (M%4 padding for the blockwise-fp8 GEMM)** — hybrid-mode-only perf fix,
  and a no-op with prefix caching on. We use neither.
- **jschmied `fp8_m4pad_patch.py`** — same reason as above.

## Patch application order (matters)

1. `apply_ple_force_fp8.py` on a *pristine* `ple_layer.py` (patch 0 must sit above the
   Fp8Config gate before anything else inserts into that function — tsw2k's patch 7
   regex-inserts into the same function, and patch 1 appends at EOF).
2. `vllm_ple_mmap.py` EOF hook, FLA seds, `mamba_utils_guarded.py`, `patch_mamba_block_size.py`,
   `patch_qsa_exact_topk.py` (tsw2k order, unchanged).
3. `patch_ple_offload_modelopt.py`, `patch_ple_offload_multinode.py`.
4. `patch_modelopt_fp8_block_moe.py` (patch 9 — inserts into the ModelOptMixedPrecisionConfig
   class body; must run BEFORE the hybrid shim appends at EOF of the same file).
5. Hybrid shim (patch 6: modelopt.py EOF hook + qsa.py seds).
6. `patch_qsa_fp8_kv.py` (patch 10 — blazux's canonical slot: after exact-topk (5) and the
   hybrid sed (6), before the qsadet wiring (5b); the order blazux's Dockerfile proves on
   this same image).
7. kernel-det build + `qsadet_patch.py` (last: it rewrites the same `qsa.py` the exact-topk
   patch touched; qsadet composes — `VLLM_QSA_EXACT_TOPK` wins when set, else DET, else stock).

Patch 11 (`patch_checkpoint_config.py`) is NOT a build step: the launcher runs it on forge
against the mounted checkpoint, stages the aliased config copies on every node, and
bind-mounts them over `/models/qwen38/config.json` + `hf_quant_config.json` in the container
(the NVMe copy is never modified — MiaAI's pattern).

All Python patchers `ast.parse` their output and refuse loudly if a target line moved
(guarded rebase detection), so an upstream image change fails the build instead of
silently producing a mis-patched image.
