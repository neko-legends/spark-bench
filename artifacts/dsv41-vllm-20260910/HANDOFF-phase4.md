## 2. Method (non-negotiable)
- One variable at a time vs the current best ("champion"). Each arm: full relaunch if the knob needs it, warmup, then **≥3 reps** of the short bench; report **median AND the per-rep values** (we are hunting bimodality — a median alone hides it). Metrics per arm: C1 per-stream on coding/math/prose (Tony set), C1 `bench-decode` 2048-tok (3 reps), C4 aggregate, cold prefill @8k and @32k, TTFT@2k, DSpark accept length (from vLLM SpecDecoding metrics), power draw + gpuflip snapshot (fast/slow) per node, `free -g` + swap.
- **Accept** an arm only if the median gain is > 3% beyond boot-to-boot drift (measure drift once: relaunch the baseline twice, bench both) AND the correctness gates pass on that arm: arithmetic, tool round-trip repro, corrcheck 7/7, NIAH 32k. Reject silently-degrading arms (e.g. accept-length drops with no throughput gain).
- Build the champion incrementally: after each accepted arm, the champion = previous champion + arm. At the end run a **combo verification**: champion vs original baseline, A/B/A (baseline→champion→baseline), 3 reps each, at the final context.
- Never leave the cluster without a working world. If an arm fails to boot or fails gates, relaunch the last champion before moving on. Keep a `CHAMPION.env` file (`/home/jun/dsv41-vllm/CHAMPION.env`) with the exact env for the current best, updated after every acceptance — and commit it to spark-bench each time.
- Backup cadence: after EVERY accepted arm and at every stage boundary, rsync `launch-dsv41-vllm-tp4.sh`, `CHAMPION.env`, any patch deltas, bench json/md, STATUS.md into `/home/jun/git/spark-bench/artifacts/dsv41-vllm-20260910/phase4/` and commit+push. Jun asked for this explicitly.
