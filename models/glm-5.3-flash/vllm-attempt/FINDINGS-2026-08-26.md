# GLM-5.3-Flash on GB10 via vLLM — findings (2026-08-26)

vLLM per-model image `vllm/vllm-openai:glm53-flash-arm64-cu130` (vLLM PR #53906
branch, `0.1.dev20051+g487ecf187`), model `LibertAIDAI/GLM-5.3-Flash-NVFP4`
(weight-only NVFP4, ~181 GiB), 4x DGX Spark (GB10, sm_121) TP4 over the CX-7
fabric. Adapted from barrydeen/glm53-flash-dgx-spark (2-node TP2 → 4-node TP4).

**Verdict: blocked on GB10.** The model's attention geometry is unsupported by
every MLA kernel this image ships for sm_120. Full chain below.

## What works
- Image boots aarch64; `Glm5NextForConditionalGeneration` + `Glm5NextMTPModel`
  registered; GB10 (12,1) detected.
- NCCL TP4 mesh over RoCE (192.168.2.0/24). PYNCCL all-reduce (SymmMem/multicast
  correctly disabled — sm_121 unsupported but harmless).
- NVFP4 quant detected (`quant_algo=NVFP4`, method=`modelopt_fp4`).
- MTP config (`method='mtp', num_spec_tokens=3`) parsles; double weight load.
- **Dense decode works** once the sparse indexer is disabled (TRITON_MLA).

## Kernel gate failures (each was a distinct layer)

| # | Phase | Error | Fix |
|---|---|---|---|
| 1 | compose/entrypoint | image entrypoint `["vllm","serve"]` ate my `bash -lc` wrapper → `exec` no-op | `entrypoint: [bash,-lc]` + single-arg command list |
| 2 | KV-cache init | `concat_and_cache_mla: pe_dim must be 64 for fp8_ds_mla` | `--kv-cache-dtype bfloat16` |
| 3 | attention backend (decode) | `TRITON_MLA: sparse not supported` / `FLASHINFER_MLA_SPARSE_SM120: kv_cache_dtype not supported` | force dense: patch `is_v32 = False` in `models/glm5next/nvidia/attention.py` |
| 4 | MLA prefill backend | `FLASH_ATTN: not support MLA dims (nope=256, rope=0, v=256)` | **no backend available** |

## Root cause (unified with the SGLang attempt)

GLM-5.3-Flash attention = **NoPE MLA** (`qk_rope_head_dim=0`) + **DeepSeek sparse
indexer** (`index_topk=2048`, `index_kpool=4`) on 11 of 45 layers (rest KDA linear).

Both engines' MLA kernels are built for **DeepSeek-V3.2 geometry** and can't run
GLM-5.3:

- SGLang: kpool needs FA3/TileLang/TRTLLM — none support sm_121; the sm_121-safe
  `flashmla_sparse` has no kpool. (`dsa_backend.py::_check_kpool_tail_backend`)
- vLLM: `flash_attn.py::FlashAttnPrefillBackend.supports_mla_dimensions` accepts
  exactly three tuples — (128,64,128), (192,64,256), (64,64,128) — all rope=64.
  GLM is (256,0,256). FlashInfer sparse-MLA (sm_120) is fp8-only + rope=64.

On datacenter Blackwell (sm_100) Z.ai ships/uses custom kernels (the image's
`models/glm5next/nvidia/` ships their TRT-LLM/FlashInfer paths); the public
arm64 image simply does not carry an sm_121-compatible kernel set for this
geometry. `gb10` is not on the vendor's verified list (H100/B200/GB200).

## Escape hatch that got us furthest
Dense fallback: patch `models/glm5next/nvidia/attention.py:534`
`self.is_v32 = getattr(config,"index_topk",None) is not None` → `= False`
(the vLLM authors left `# self.is_v32 = False` commented in — they tested dense
too). Decode then runs on TRITON_MLA. Prefill still has no NoPE backend.

## Paths forward (in effort order)
1. **Wait for upstream** — vLLM PR #53906 (glm5_next) maturing; flashinfer sm_121
   sparse-MLA + a NoPE prefill path. Day-1 experimental support.
2. **NoPE MLA prefill triton kernel** registered via vLLM's
   `register_mla_prefill_backend` plugin hook (decode already works; prefill is
   the single missing piece). ~hours of work + correctness testing, not a flag.
   MLA-without-rope is *simpler* than the DeepSeek case (no rotary component),
   so a triton prefill kernel is tractable.
3. Faking rope dim (NO — changes model semantics, produces garbage).

## DECISION (2026-08-26): stop, wait for DFLASH2
GLM team is producing a **DFLASH2** variant. Decision: stop hand-building GB10
kernels and wait for it rather than port the sparse/NoPE-MLA geometry ourselves.
The NoPE MLA prefill plugin (`../nope_mla.py` + `../sitecustomize.py`) is built,
committed, and in-process-verified (override resolves + accepts (256,0,256)); it
is the starting point if we ever re-attempt before upstream lands. Production
restored to DeepSeek V4 Flash (4x TP4) + Kai's emergence build resumed.
