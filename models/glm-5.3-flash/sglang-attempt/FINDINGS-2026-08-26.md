# GLM-5.3-Flash on GB10 via SGLang — findings (2026-08-26)

Four bring-up attempts of `lmsysorg/sglang:glm-5.3-flash` (arm64, branch build
`0.0.0.dev1+gf13cb6f6a7`, from SGLang PR #36507) on a 4x DGX Spark (GB10, sm_121)
TP4 cluster over the switched CX-7 fabric (RoCE, `enp1s0f1np1`, `192.168.2.0/24`).

**Verdict: hard-blocked on GB10.** Root cause is a kernel-capability gap, not
configuration. Details below; the working scripts are in this directory
(`glm-tp4-run.sh` — final state, attempt 4 flags).

## What works on GB10 (proven during attempts)

- Image runs on aarch64; `glm5_next` / `glm5_next_nextn` model classes present.
- Tokenizer, config parse, fp8 (e4m3) checkpoint detection.
- Weight load across TP4: ~74.8 GB per node, ~185 s, no errors.
- NCCL mesh across 4 nodes over RoCE (`Init torch distributed ends`, TP group
  formed; `CustomAllreduce`/`multimem all-gather` correctly disabled cross-node).
- MoE via `deep_gemm`; multimodal via `triton_attn`.
- MTP draft layer setup (adaptive NEXTN 5/1/6 config parses).

## Kernel support matrix (GB10 / sm_121)

| Kernel path | Status | Error signature |
|---|---|---|
| TileLang DSA | ❌ | `tvm.error.InternalError: Failed to set the allowed dynamic shared memory size to 151552` (148 KB dynamic smem > GB10 per-block limit) |
| TRT-LLM DSA / FMHA | ❌ | `Error in function 'TllmGenFmhaRunner' at .../fmhaRunner.cuh:37: Unsupported architecture` (built for sm_100/110) |
| flashinfer trtllm-gen FMHA (any consumer) | ❌ | same `Unsupported architecture` |
| FA3 DSA | ❌ (Hopper-only) | not attempted; sm_90 kernels |
| flashmla_sparse DSA | ⚠️ loads, but **no kpool support** (see below) | `NotImplementedError: index_kpool > 1 ... only supported by FA3/TileLang/TRTLLM` |
| triton (any path) | ✅ works (slow) | — |
| deep_gemm MoE (fp8) | ✅ | — |

## The actual blocker: kpool

GLM-5.3-Flash's sparse indexer uses `index_kpool > 1` (kpool compression).
In `sglang/srt/layers/attention/dsa_backend.py`:

- `_check_kpool_tail_backend` raises `NotImplementedError` unless the backend
  is FA3 / TileLang / TRTLLM.
- `_resolve_kpool_tail_backend` force-overrides `flashmla_sparse` → `trtllm`
  whenever `device_sm_major >= 10` — which matches GB10 (sm_121) even though
  the trtllm-gen FMHA kernels are not built for sm_121.

So there is no legal backend combination: every kpool-capable backend is
sm_121-incompatible, and the sm_121-compatible backend has no kpool. Fixing
this needs an sm_121-capable kpool kernel (flashmla_sparse kpool support, or
trtllm-gen FMHA built for 12.1a) — upstream work, not a flag.

## Secondary trap (worth knowing even post-kernel-fix)

The MTP/EAGLE **draft worker resolves its own attention backend**
(`sglang/srt/speculative/draft_worker_common.py::_resolve_draft_attention_backend_fallback`):
`dsa` is not in `DRAFT_ATTENTION_BACKEND_CHOICES`, so it silently falls back to
`flashinfer` → trtllm-gen FMHA → the same `Unsupported architecture` crash,
*regardless of your `--dsa-*-backend` flags*. We pinned
`--speculative-draft-attention-backend triton` (only GB10-safe choice in the
list) and that path engaged correctly ("Overriding draft attention backend to
triton") — the crash then came from the *target model's* DSA path (kpool above).

## Bring-up gotchas (config-level, all solved)

1. Mount `/dev/infiniband` into the container + `--cap-add IPC_LOCK` +
   `ulimit memlock=-1` — without it, `ncclCommInitRank` fails with
   `NCCL error: invalid usage`.
2. Multi-node: `--nnodes 4 --node-rank N --dist-init-addr <rank0-wired-IP>:5000`.
   Rank 0's rendezvous waits ~10 min; workers must be up first.
3. Watch for stale duplicate routes on the fabric subnet (one of our nodes had
   a leftover mesh-config address on a down interface hijacking `192.168.2.0/24`
   → `EHOSTUNREACH` on the TCPStore connect).
4. Don't ssh to the wired fabric IPs — no sshd there; control plane over
   Tailscale/LAN, data plane over CX-7 via NCCL env pinning.

## Recipe reference

The config that got furthest (all init OK, dies only at DSA graph capture):
`--quantization fp8 --kv-cache-dtype bfloat16 --attention-backend dsa
--dsa-prefill-backend flashmla_sparse --dsa-decode-backend flashmla_sparse
--linear-attn-backend triton --moe-runner-backend deep_gemm
--speculative-algorithm NEXTN --speculative-num-steps 5 --speculative-eagle-topk 1
--speculative-num-draft-tokens 6 --speculative-adaptive
--speculative-draft-attention-backend triton ...` (full command in
`glm-tp4-run.sh`).
